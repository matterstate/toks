# Final native encoder comparison

> Historical migration record through `17ec6e9`. The C reference is retired;
> current regression and canary checks are in [validation](../validation.md).

The Rust encoder is modestly faster over this fixed matrix in aggregate, with
larger wins on some SentencePiece and WordPiece workloads. It does not win every
cell. Python adapter overhead is measured separately and remains slower than C.

These are **native-CPU-tuned** builds, not the portable default binaries. The
core revision is `77e5448`; C is frozen at `55a5230`. Both use optimization level
3 and thin LTO. Rust uses one codegen unit and `target-cpu=native`; C adds
`-mcpu=native` on arm64 or `-march=native` on x86, retaining its aliasing
and wrapping-arithmetic build flags. Toolchains and exact binary hashes are in
the raw receipts. The existing native assembly kernels are shared.

The matrix contains seven tokenizers × four public corpora × three chunk settings:
84 cells per host. Chunks are cut at the first newline at or beyond 64 or 4096
bytes; “whole” is one call for the full corpus. Seven alternating ABBA/BAAB blocks
contain two C and two Rust processes each; each process records eleven inner
repetitions per state. Inner repetitions are not independent observations.
Linux is pinned to CPU 8. macOS uses the normal scheduler. Loading, scratch
initialization and exact-output validation are outside the timed region.

Each cell below uses the geometric mean of **paired block median-time ratios**.
Parentheses contain exploratory 95% percentile-bootstrap intervals over the
seven whole blocks, with 10,000 resamples. These quantify observed timing variation
on the fixed inputs, not generalization to other workloads. Ratios above 1 favor
Rust. Aggregate rows weight all selected cells equally; no losses are discarded.

“Fresh scratch” empties semantic caches before every call; CPU caches can remain
hot. “Stream” is a pass starting with empty semantic caches after the same text
was processed previously (`pass_after=same`). “Replay” immediately repeats it.
The default benchmark cache budgets are retained. These are distinct workloads.

The shortest fresh-scratch arm64 group regresses slightly (0.993×). Byte-BPE
mostly stays near parity. Gemma English whole-document fresh-scratch encoding
measures 1.209× on arm64 and 1.232× on x86; WordPiece CJK at 4096 bytes measures
1.095× and 1.069×. Some Unigram fresh-scratch cases and other cells lose.

All 4,704 timed processes pass complete token-stream equality checks against C.
The 84 stream digests also agree across architectures, and all 28 overlapping
4096-byte cases match the original pre-optimization C goldens. The benchmark
caller independently checks cold/warm ID equality before timing.

## Reproduction and receipts

`tools/rust-port/corpora.py` reconstructs the pinned public inputs, including the
code corpus from the frozen upstream Git revision, and rejects changed hashes.
The original upstream private 23-file corpus was unavailable and is not represented
as tested. The public manifest is `receipts/corpora.json`.

Build Rust with `RUSTFLAGS="-C target-cpu=native" cargo build --release`.
Build C through `Makefile.reference` with the flags above in a separate output
directory. Link each archive to the same `tools/bench/e2e.c` with the matching
native C-driver flag, `-lpthread -lm` (plus `-ldl -lrt -lutil` on Linux), and thin
LTO for the C reference. Then run:

```sh
python3 tools/rust-port/bench.py --c <c-e2e> --rust <rust-e2e> \
  --chunks 64 4096 0 --rounds 7 --reps 11 --out <results-dir>
# Add --cpu 8 on the measured Linux host.
python3 tools/rust-port/report.py <results-dir>/results.json \
  --out <results-dir>/paired.json
```

Full process metrics, inner repetitions, loads, toolchains and hashes are in
`receipts/final-native-{arm64,x86}.json.gz` (ordinary gzip-compressed JSON).
Paired estimates are in `receipts/final-native-{arm64,x86}-paired.json`; stream
hashes are in `receipts/final-native-goldens.json`. The raw pooled-median ratios
are preserved too, but the tables consistently use paired block estimates.
The run durations were 23.2 minutes on arm64 and 28.1 minutes on x86.
